# Энергопотребление Android

Принцип: **вне разрешённых Wi‑Fi программа не существует** — ни процессов
с работой, ни опросов. Внутри разрешённой сети — только блокирующие
системные ожидания.

## Вне разрешённых сетей (0%)

- `CallService` полностью остановлен (`stopService`): нет сокетов, слушателей
  телефонии, таймеров и wakelock'ов.
- Единственное, что когда-либо будит процесс, — системный `JobScheduler`
  (`GateJobService`, период ≥15 мин, `setPersisted`, doze-aware): проверка
  текущего SSID занимает миллисекунды, Android объединяет такие задачи
  с другими работами системы.
- Дополнительные проверки — только при загрузке телефона (`BootReceiver`),
  открытии приложения и изменении настроек.
- Приложение само **не инициирует Wi‑Fi сканирований** (читает уже известный
  системе `WifiInfo`) — сканирование сети самая дорогая операция.

## В активном режиме (разрешённая сеть)

- Foreground service с уведомлением низкой важности (по требованию Android
  для живучести); один поток заблокирован на `ServerSocket.accept()`,
  второй источник событий — системный broadcast состояния телефонии.
- `PARTIAL_WAKE_LOCK` берётся **только** на время отправки события звонка
  на ПК, максимум 15 секунд, и отпускается в `finally`.
- Нет периодических ping/keep-alive к ПК: если ПК недоступен, одна попытка
  отправки — и тишина (повторы не плодятся в фоне).
- Открытие звонилки по команде с ПК — обычный `ACTION_DIAL`, сети не требует.

## Рекомендации пользователю

- Отключить для Zadachi оптимизацию батареи (кнопка в приложении), чтобы
  OEM-прошивки (Xiaomi/Samsung и т.п.) не убивали сервис в разрешённой сети.
- Не добавлять в белый список публичные Wi‑Fi: там сервис будет жить постоянно.
- Геолокация нужна Android только чтобы отдавать SSID; своих запросов
  местоположения приложение не делает.
